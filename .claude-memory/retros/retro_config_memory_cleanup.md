## Surprise

- **The brief's premise for the memory import was wrong, and I could see it was wrong in my own context.** PR2 step 4 said "nothing committed tells Claude Code to load `.claude-memory/MEMORY.md`" and proposed an `@import`. But auto-memory *already* loads MEMORY.md every session via Drew's symlink — the index was sitting in my context that session. Adding the import would have loaded 16 KB twice. The convention wasn't missing; it was invisible because it was already working. Resolved with a prose pointer + a setup script instead of the import.
- **"No duplication" and "works on any fresh machine" are in genuine tension, by design.** Claude Code keeps auto-memory machine-local (home dir); the `autoMemoryDirectory` override is absolute-or-`~/` only, so there's no *committed* portable config that points auto-memory at the in-repo `.claude-memory/`. The primary machine needs auto-memory pointed at the repo (which loads the index); a fresh clone needs the `@import` (which then double-loads on the primary). Drew's call: keep auto-memory + a committed `link-claude-memory.ps1` (one command per new machine) rather than the lossy `@import`-plus-disable-auto-memory alternative.
- **The one file the brief said to delete had no retro and held content tracked nowhere else.** `project_wishlist_rework_arc.md` self-flagged "RETIRE AFTER NEXT SYNC," but unlike the other DONE arcs it had no retro, and it carried two deferred ideas ("auto-resolve wishlist hit on save," "web `/bookshop` wishlist tab") absent from TODO.md and code. Deleting per the brief would have silently dropped them. Captured as TODO #57 first, then deleted.
- **Two "safe" dependency updates weren't.** The dependabot batch surfaced that NSubstitute 6.0 tightened its `Arg.Is<T>` matcher-lambda nullability, tripping CS8602 across ~17 test sites under warnings-as-errors — a code-change bump wearing a minor-looking number. And the working tree already carried an accidental Application Insights 3.x bump: the *one* package on the dependabot ignore list (it removes `ITelemetryInitializer`, TODO #42), and the actual thing breaking compilation — not the AngleSharp audit Drew came in about.

## Lesson

- **Only path-scoped rules actually reduce per-session context.** `@import` and auto-memory both load at launch — they organise context, they don't shrink it. The lever is `.claude/rules/` with `paths:` frontmatter: those files load *only* when a matching file is touched. Moving the nine Blazor/MAUI gotchas into `.claude/rules/blazor-mudblazor.md` (`BookTracker.Web/**`) and `maui-mobile.md` (`BookTracker.Mobile/**`) means a session working purely in `BookTracker.Data` no longer carries UI-framework trivia it can't use. That was the actual point of the whole exercise; the MEMORY.md regroup and the Shipped archive are tidiness, but the rules move is the context win.
- **Verify a config mechanism against the live docs before trusting a brief's snippet.** The permission-deny syntax, the rules `paths` frontmatter, and the `@import` external-path behaviour all needed checking against `code.claude.com/docs`. The brief's "first session shows a one-time import-approval dialog" was wrong — that dialog only fires for imports resolving *outside* the working directory, and `.claude-memory/` is in-repo. A brief is a plan, not ground truth; the docs and the files on disk are.
- **When retiring a progress-memory file, grep its deferred items against TODO and code first.** A file's own "RETIRE" flag means its *author* thought it was done, not that its content is captured elsewhere. The wishlist file's two orphaned ideas would have been lost on a reflexive delete. Same discipline as "grep result is a checklist": every item in the retiring file gets classified (captured / re-home / drop) before the file goes.
- **"Safe, no code changes" is a claim the build settles, not the version-bump type.** A minor can be safe; a major can be trivial; a major that tightens nullable annotations under TWAE is a code-change bump. The right gate is: apply, build `--no-incremental`, run the affected tests; if it compiles clean and stays green it's safe, if not it's held — regardless of whether semver called it minor or major.

## Quotable

The memory-import moment is the one worth telling. The brief — written by another agent reviewing the repo from outside — said the setup was missing a way to load the memory index, and proposed adding one. But I was reading that index *as I read the brief*. Auto-memory had loaded it at session start, the way it does every session, through a symlink Drew set up months ago. The convention the brief wanted to add already existed; it was just doing its job quietly enough that a reviewer looking at committed files couldn't see it. The fix wasn't to add a loader. It was to notice the one already running and not stack a second copy on top of it — and then to write down, in the file a future reviewer *will* read, that the load happens and where. The cleanest thing you can do for a system that already works is make the fact that it works legible, without changing what it does.

The deeper reframe from restructuring MEMORY.md: the durable memory isn't a document I recite top-to-bottom each session. It's an index that tells me which drawer to open when the topic comes up — and most of it I never open. Grouping it into sections and pushing the framework-specific gotchas behind path triggers wasn't "shortening a document." It was filing the cabinet so the drawer I need opens without the other drawers spilling out onto the desk every time.
